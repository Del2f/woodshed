# Woodshed 🎸

일렉기타 개인 연습실. 내 음원으로 구간 반복 연습을 하고, 곡의 코드 흐름과 지판 위 코드톤을 보고, 카피한 릭을 타브로 적어 두고 잊을 때쯤 다시 복습합니다. 연습 기록은 클라우드에 영구 저장됩니다.

> *woodshed*: 영어권 연주자들이 "혼자 틀어박혀 연습한다"는 뜻으로 쓰는 속어

**사이트:** https://del2f.github.io/woodshed/ · 개인 취미 프로젝트 (가입은 막혀 있음)

## 단축키

**플레이어** — `Space` 재생/정지 · `A` / `B` 구간 시작/끝 · `L` 반복 · `←` `→` 5초 이동 · `[` `]` 속도 ±5% · `0` 구간 처음으로 · `↑` `↓` 볼륨 ±5% · `M` 음소거

**파형 확대·축소** — `Ctrl`(⌘) + 휠 또는 핀치(마우스 위치 기준) · `=` `-` 확대/축소 · `Z` 구간에 맞춰 확대 ↔ 전체 보기. 확대하면 미니맵의 주황 상자를 끌어 이동하고, 구간 끝은 0.01초·0.1초·1박 단위로 조정합니다.

## 릭을 카피하고 잊지 않기

1. 플레이어에서 카피할 부분을 드래그해 구간을 만들고 **이 구간을 릭으로**를 누릅니다.
   마디 수·튜닝·BPM이 채워진 빈 타브가 열리고, 위에는 원곡 구간이 반복 재생됩니다(속도 조절, 기타만 듣기 가능).
2. (선택) **음원에서 타브 초안**: *솔로·멜로디* 또는 *리프·코드*를 고르고 **초안 만들기**. 민감도를 바꾸면 엔진을 다시 부르지 않고 바로 다시 채웁니다. 틀린 음은 직접 고칩니다(`Ctrl+Z`로 되돌리기 가능).
3. 타브를 적으며 기타 소리로 들어 보고(속도·반복·클릭·드라이브), 태그·메모·목표 BPM을 붙입니다.
4. 다음 날부터 홈 화면과 릭 보관함에 **오늘 복습할 릭**이 뜹니다. 쳐 보고 *다시 / 어려움 / 보통 / 쉬움*을 고르면, 잘 기억할수록 복습 간격이 길어집니다(최대 1년). 그날 친 BPM을 적으면 최고 기록이 쌓입니다.

## 데이터는 어디에 저장되나요?

```
음원 파일 (mp3, wav, flac …)         → 내 PC에서 바로 읽음. 어디에도 업로드하지 않음
곡 · 구간 · 연습 기록 · 분석       → Supabase (로그인 전에는 이 브라우저의 IndexedDB)
릭 · 퀴즈 기록                        → Supabase (위와 같음)
분리된 기타 트랙                      → 엔진 캐시(~/.woodshed/cache) + 브라우저(IndexedDB)
주간 백업                             → 비공개 GitHub 저장소 Del2f/woodshed-backup
수동 백업                             → 설정 화면에서 JSON 내려받기·불러오기
```

- 음원 폴더 연결은 **Chrome / Edge**에서 됩니다(File System Access API). 다른 브라우저에서는 연습할 때마다 파일을 직접 고릅니다.
- 음원 폴더를 OneDrive·구글 드라이브 동기화 폴더로 고르면 음원도 함께 백업됩니다.

### 자동 백업 (비공개 저장소)

비공개 저장소 `Del2f/woodshed-backup`의 GitHub Actions가 **매주 월요일 03:23(한국 시간)** 에 Supabase 전체를 `woodshed-backup.json`(앱 백업 형식)으로 저장합니다. 지난 백업은 커밋 기록에 주마다 남고, 복원은 **설정 → 백업 불러오기**로 합니다.

- 내보내기 스크립트: [`scripts/backup.ts`](scripts/backup.ts) (1000행이 넘는 표도 나눠서 전부 받음)
- 그 저장소에 `SUPABASE_URL`(Variables)과 `SUPABASE_SERVICE_ROLE_KEY`(**Secrets**)가 있어야 합니다. `service_role` 키는 RLS를 건너뛰는 관리자 키라서 공개 저장소·브라우저에는 절대 넣지 않습니다.

## 로컬 분석 엔진

음원 분석·기타 분리·타브 초안은 **내 PC에서만** 돌아가는 Python 서버([`engine/`](engine/), FastAPI)가 합니다. 음원은 `127.0.0.1:8765`로만 전송되고 인터넷으로 나가지 않습니다.

1. Python 3.10 이상 설치 ([python.org](https://www.python.org/downloads/))
2. [`engine/start.bat`](engine/start.bat) 더블클릭 — 켤 때마다 필요한 패키지를 확인합니다. 창이 열려 있는 동안 엔진이 켜져 있습니다.
3. (선택) 기타 트랙 분리: [`engine/install-separation.bat`](engine/install-separation.bat) 한 번 실행 (PyTorch CUDA + BS-RoFormer, 약 3GB). 분리 모델 파일(약 700MB)은 처음 분리할 때 받습니다.
4. 처음 분석할 때 Chrome이 **로컬 네트워크 접근** 권한을 물으면 *허용*.
5. 업데이트 후에는 엔진 창을 닫고 `start.bat`을 다시 실행합니다. 엔진 창에 버전과 `기타 분리: bs_roformer_sw`, `음 받아 적기: 사용 가능`이 보이면 됩니다.

| 기능 | 방식 |
|---|---|
| 박자·BPM | librosa 비트 추적 → 절반·두 배 템포 보정(백비트 주기, 박 사이 타격) → 화성·베이스 변화로 마디 첫 박 (4/4 가정) |
| 베이스 | 저음 대역에서 '가장 낮게 울리는 음' — 디스토션 배음은 기본음 위에만 생겨 근음을 잘 알려 줌. 기타 분리를 켜면 기타 뺀 트랙에서 찾음 |
| 키 | 크롬마 · 베이스 분포 · 코드 근음 분포 × Krumhansl-Kessler, 나란한조는 첫 코드·베이스로 으뜸음 판별 |
| 코드 | 박 단위 크롬마 × 배음을 넣은 템플릿 + 베이스 근음 + Viterbi, 3도가 잡음 위로 솟지 않으면 파워코드 |
| 음원 읽기 | libsndfile, 실패하면 PyAV(FFmpeg)로 — 일부 MP3·M4A 대응 |
| 기타 분리 | **BS-RoFormer SW** (6분리, 로컬에서 쓸 수 있는 공개 모델 중 기타 분리 평가 최상위 — MVSEP Multisong 기타 SDR 9.05). [bs-roformer-infer](https://github.com/openmirlab/bs-roformer-infer)(MIT, 고정 커밋)로 실행. RTX 3080 기준 30초 음원 약 6초, 그래픽 메모리 약 3GB. 예비: Demucs `htdemucs_6s`. 예전 모델로 분리한 곡은 *다시 분석*하면 새로 분리 |
| 음 받아 적기 | Spotify [Basic Pitch](https://github.com/spotify/basic-pitch) 모델(Apache-2.0, ONNX). **솔로 모드**: 비터비로 가장 두드러진 한 줄기만 따라가 섞여 든 리듬 기타를 거르고, 음높이 곡선으로 벤딩·해머링 구분. **리프·코드 모드**: 시작점·음 길이, 배음 유령 음 제거, 이어지는 음높이 변화는 벤딩 |
| 줄·프렛 배치 | 브라우저에서: 분석의 마디선으로 박자 칸 맞추기 → 비터비로 손 위치 이동이 가장 적은 줄·프렛, 레가토는 같은 줄에, 해머링·풀링 추정 |

결과는 `~/.woodshed/cache`에 캐시되어 같은 파일은 바로 다시 열립니다. 분리된 기타 트랙은 분석 직후 브라우저에도 저장되므로 **재생할 때는 엔진이 필요 없습니다.** 분석 결과(JSON)는 Supabase `analyses` 표에도 저장되어 다른 PC에서도 코드 흐름을 볼 수 있습니다.

### 정확도에 대해 (솔직하게)

- **자동 분석은 참고용입니다.** 디스토션 메탈 리프 합성 음원(기준값 조정에 쓰지 않은 8곡)에서 BPM 7/8, 키 6/8, 코드 4개 완전 일치 4/8 수준이고, 실제 녹음은 체계적으로 검증하지 않았습니다. 곡 정보의 키·BPM은 직접 고친 값이 우선합니다.
- **타브 초안은 초안입니다.** 합성 시험에서는 리듬 기타가 깔린 멜로디 7음과 온음 벤딩을 솔로 모드가 정확히 적었지만, 실제 곡을 정답 악보와 비교하지는 않았습니다. 디스토션 파워코드는 근음을 놓치거나 배음을 음으로 적을 수 있고, 리듬 기타가 솔로만큼 크면 그쪽으로 끌려갈 수 있습니다.
- 2026년 10월 기준 더 최신 기타 전사 모델(TART, 고해상도 기타 전사 등)은 논문은 있지만 내려받을 수 있는 모델이 공개되지 않아 쓰지 못했습니다.
- BS-RoFormer SW 모델 가중치의 라이선스는 '알 수 없음'입니다. 개인 PC 취미 용도로만 씁니다.

```bash
cd engine
.venv\Scripts\python -m pytest     # 엔진 테스트 55개 (합성 음원으로 BPM·키·코드·마디·받아 적기·분리 캐시)
```

## 개발

```bash
npm install
```

Supabase를 연결하지 않아도 바로 쓸 수 있습니다. 이때는 **로컬 모드**라서 브라우저 사이트 데이터를 지우면 기록이 사라질 수 있습니다.

**기술:** Vite 5 · React 19 · TypeScript · wavesurfer.js 7 (Regions·Timeline·Minimap) · idb-keyval · supabase-js · Web Audio (메트로놈·타브 합성음: Karplus-Strong + 올패스 소수 지연) · Python FastAPI · librosa · PyAV · ONNX Runtime · PyTorch

### Supabase 연결 (영구 저장)

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 만듭니다. 무료 플랜이면 충분합니다.
2. **SQL Editor**에서 [`supabase/migrations/`](supabase/migrations/)의 SQL을 번호 순서대로 실행합니다 (`0001_init.sql`, `0002_analyses.sql`, `0003_licks.sql`, `0004_quiz_results.sql`).
3. **Authentication → URL Configuration**
   - Site URL: 배포 주소 (예: `https://del2f.github.io/woodshed/`)
   - Redirect URLs에 `http://localhost:5173/**` 와 배포 주소를 추가합니다.
4. **Project Settings → API**에서 `Project URL`과 `anon public` 키를 복사합니다.
5. 로컬 개발: `.env.example`을 `.env.local`로 복사하고 두 값을 채웁니다.
6. 처음 로그인해 계정이 만들어지면 **Authentication → Sign In / Providers**에서 *Allow new users to sign up*을 끕니다. 데이터는 RLS로 본인만 볼 수 있습니다.

> `anon` 키는 브라우저에 공개되는 용도라서 저장소에 올라가도 괜찮습니다. 데이터는 로그인과 RLS가 보호합니다. `service_role` 키는 절대 넣지 마세요.

### GitHub Pages 배포

1. **Settings → Pages → Source**를 *GitHub Actions*로 바꿉니다.
2. **Settings → Secrets and variables → Actions → Variables**에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 등록합니다.
3. `main`에 push 하면 테스트·빌드·배포가 자동으로 실행됩니다. `engine/`이 바뀌면 엔진 테스트도 돕니다.

**Supabase 휴면 방지:** 무료 플랜은 7일 동안 요청이 없으면 일시정지됩니다. [`supabase-keepalive.yml`](.github/workflows/supabase-keepalive.yml)이 3일마다, 백업 저장소가 매주 요청을 보내 깨워 둡니다. GitHub은 60일 동안 커밋이 없으면 예약 워크플로를 끄므로 가끔 Actions 탭을 확인하세요.
